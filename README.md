# ALS_Multicohort

Analysis code for:

> Guo K, Wang Z. *Cross-platform validation of an ALS glial transcriptomic signature reveals a ventral-horn myeloid–glial response.* Manuscript submitted to *Molecular Neurodegeneration*.

The study uses a donor-level discovery cohort (GSE330130) only to define candidate ALS-up and ALS-down modules from astrocyte-compartment nuclei. It then tests them in five external single-nucleus contrasts from four studies and in the NYGC ALS Consortium bulk RNA-seq resource, under a time-stamped analysis plan with sixteen amendments. Exploratory analyses place the reproducible programme in its cell-source, pathway, ligand-receptor and Visium spatial context.

## Contents

| Path | Contents |
|---|---|
| `scripts/` | All analysis scripts, Python and R (see the pipeline below) |
| `scripts/figures_v2/` | R panel scripts (ggplot2 + patchwork); `compose_figures_v3.R` assembles the submitted main Figures 1-5, Supplementary Figures S1-S10 and the graphical abstract |
| `docs/analysis_plans/` | The frozen analysis plan (v1.0) and Amendments 1-16, byte-identical to the files whose SHA-256 values are listed in Supplementary Table S1 |
| `docs/analyses/` | One README per analysis (W32-W74): design, results and reading |
| `docs/supplementary_tables/` | Supplementary Tables S1-S4 (TSV), as submitted |
| `metadata/` | Small sample manifests derived from public metadata and read by the scripts |

This repository contains **no data**. All inputs are public (see [Data sources](#data-sources)), and every result table is regenerated by the scripts.

## Requirements

- **R** 4.5 with edgeR, limma, metafor, survival, readxl, fgsea, msigdbr, liana, SeuratObject, Matrix, ggplot2, patchwork, svglite, ragg and ggrepel (`environment/R_packages.tsv`).
- **Python** 3.10 or later with pandas, numpy, scipy, statsmodels, anndata, h5py and openpyxl (`environment/requirements.txt`).
- Running everything takes a few hours on a laptop. The longest single step is `run_w58_multicohort_meta.R` (about 12 min).

## Prespecification and version history

The analysis was run in a private working repository. That repository also holds intermediate data files that are not redistributed here.

- The analysis plan and every amendment were committed there before the analyses they govern. Supplementary Table S1 lists those commit hashes and times, and the SHA-256 of each plan file. The files in `docs/analysis_plans/` are byte-identical, so the checksums can be verified directly:

  ```bash
  shasum -a 256 docs/analysis_plans/*.md
  ```

- The commit hashes in S1 and in Figure 1b refer to that private history. For this reason, `build_v2_supplementary_tables.py` (S1) and Figure 1b need that history to regenerate. All other tables and figures do not.
- The deviations from the plan are listed in Supplementary Table S3. Every test of the modules, including null, post hoc and superseded ones, is listed in S2.
